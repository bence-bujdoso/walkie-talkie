================================================================================
2. PARSING METHODS
================================================================================

TK11.exe contains TWO firmware parsing methods:

A) PareUpdataFile(string path) -> byte[]
   - Primary/newer format parser
   - IL Code Size: 806 bytes (complex)
   - Local variables include:
     * FileInfo, FileStream
     * Multiple byte[] buffers
     * UInt16 (likely CRC16)
     * UInt32 (likely file size or checksum)
     * String for version
     * Int32 for offsets

B) PareUpdataFile1(string path) -> byte[]
   - Legacy/fallback format parser
   - IL Code Size: 587 bytes (simpler)
   - Similar structure but less complex
   - Also uses UInt16 (CRC16)

The Updata() method calls:
  1. First tries: PareUpdataFile()
  2. If fails, tries: PareUpdataFile1()
  3. If both fail, shows error: "文件版本错误" (File version error)

================================================================================
5. DECRYPTION/VALIDATION PROCESS
================================================================================

From IL analysis, PareUpdataFile does:

1. Opens file and checks size
2. Reads header section
3. Validates magic bytes / format identifier
4. Extracts version string from VER_POSITION
5. Compares version against expected format
6. Reads timestamp (32 bytes)
7. Calculates CRC16 over specific regions
8. Decrypts/deobfuscates the firmware data
9. Returns decrypted byte[] to downloadFileEx()

The downloadFileEx() method:
- Takes the decrypted firmware bytes
- Sends to device over serial protocol
- Does NOT recalculate CRC (already validated)

6. WHY PATCHED FIRMWARE FAILS
================================================================================

Our patched firmware fails because:

1. We modified the RAW ENCRYPTED firmware
   - Changed bytes at offsets 0x561EC (USB mode data)
   - Changed bytes at various mode configuration locations

2. BUT we didn't update the WRAPPER format:
   - CRC16 in header is now wrong
   - Version string may have changed
   - Encryption may be broken by raw edits

3. The PareUpdataFile() method detects:
   - CRC mismatch -> rejects file
   - OR version mismatch -> rejects file
   - OR decryption fails -> rejects file

4. Even with validation bypass in TK11.exe:
   - The RAW ENCRYPTED data gets sent to bootloader
   - Bootloader ALSO validates (separate validation)
   - Bootloader rejects corrupted encrypted data
