## Overview

This automated toolset enables USB (Upper Sideband) transmission on the TK11 handheld radio's 11-meter band, specifically on channel K38 (27.385 MHz).

### What This Does

- **Generates** 8 patched firmware variants with USB TX enabled
- **Bypasses** TK11.exe firmware validation
- **Enables** USB mode transmission on K38 channel
- **Removes** "DISABLE" message when transmitting in USB mode

### What You Get

- Automated firmware patcher scripts (Windows/Linux/Mac)
- dnSpy patch template for TK11.exe
- 8 firmware variants with different CRC strategies
- Complete documentation and troubleshooting guides

## How It Works

### Two-Part Patch

**Part 1: Firmware Modification**
- Location: Offset 0x314D in firmware
- Change: `0x03` → `0x13` (binary: `00000011` → `00010011`)
- Effect: Enables USB (0x04) mode bit in TX permission mask

**Part 2: TK11.exe Modification**
- Class: `K7.wfm_progress`
- Method: `Updata()`
- Change: Bypass firmware validation, load directly
- Effect: Allows flashing of modified firmware

### Why Both Parts Are Needed

1. **Firmware patch** enables USB TX in radio
2. **TK11.exe patch** allows loading modified firmware (original rejects it)

## Usage

### Quick Start (RECOMMENDED)

See **[QUICKSTART.md](QUICKSTART.md)** for simple 5-step guide.

### Detailed Process

#### 1. Generate Patched Firmware

**Windows:**
```powershell
cd bin\scripts
.\create_all_patches.ps1
```

**Linux/Mac:**
```bash
cd bin/scripts
chmod +x create_all_patches.sh
./create_all_patches.sh
```

**Output:**
```
patched_firmware_final/
├── TK11_PATCHED_v1_simple_crc16xmodem.bin
├── TK11_PATCHED_v2_crc16ibm.bin
├── TK11_PATCHED_v3_minimal.bin
├── TK11_PATCHED_v4_end_of_file.bin
└── TK11_PATCHED_v4_header_*.bin (4 files)
```

#### 2. Patch TK11.exe with dnSpy

**Open dnSpy:**
```cmd
dnSpy\dnSpy.exe bin\original\TK11.exe
```

**Navigate:**
```
TK11
└─ K7
   └─ wfm_progress
      └─ Updata()
```

**Edit:**
1. Right-click `Updata()` → "Edit Method (C#)..."
2. Open: `bin\scripts\patch_tk11_updata_method.cs`
3. Copy LEVEL 2 bypass code
4. Paste and replace entire method
5. Click "Compile"
6. File → Save Module → Save as `TK11_PATCHED.exe`

**Verify:**
- File size: ~373 KB (original is ~382 KB)
- Should start normally when double-clicked

#### 3. Flash Firmware to Radio

**Setup:**
1. Turn OFF radio
2. Connect USB cable
3. Turn ON radio
4. Open `TK11_PATCHED.exe`

**Flash:**
1. Click firmware browse button
2. Select: `patched_firmware_final\TK11_PATCHED_v3_minimal.bin`
3. Should see: "Firmware loaded (validation bypassed)"
4. Click "Write" or "Update"
5. Wait for progress bar to complete

**Results:**
- ✅ "Write success" → Proceed to testing
- ❌ "Write fail" → Try different variant (see Testing Order below)

**Firmware Testing Order:**
1. `v3_minimal.bin` (most conservative, single-byte change)
2. `v1_simple_crc16xmodem.bin` (CRC16-XMODEM at end)
3. `v4_end_of_file.bin` (CRC at EOF)
4. `v4_header_0x0C.bin` through `v4_header_0x20.bin`
5. `v2_crc16ibm.bin` (CRC16-IBM algorithm)

#### 4. Test USB TX

**Safety First:** Connect 50Ω dummy load to antenna! ⚠️

1. Radio restarts automatically after flash
2. Navigate to K38 channel (27.385 MHz)
3. Select USB mode (Menu → Modulation → USB)
4. Press PTT button
5. **Expected:** NO "DISABLE" message ✅

**Success indicators:**
- TX LED lights up
- No "DISABLE" message
- Normal transmission (can measure on spectrum analyzer)

## Troubleshooting

### Script Issues

#### "Python not found"
**Cause:** Python not installed or not in PATH
**Fix:**
```powershell
# Windows:
# 1. Install from https://www.python.org/
# 2. Check "Add Python to PATH" during install
# 3. Restart terminal

# Verify:
python --version
```

#### "Original firmware not found"
**Cause:** Files not in correct location
**Fix:**
```
# Ensure files are in:
bin/original/TK11.exe
bin/original/TK11_v5.00.09_ENG.bin

# Not just downloaded to Downloads folder!
```

#### Script permission denied (Linux/Mac)
**Fix:**
```bash
chmod +x bin/scripts/create_all_patches.sh
```

### dnSpy Issues

#### "Compilation failed"
**Cause:** Syntax error in C# code
**Fix:**
- Copy code from `patch_tk11_updata_method.cs` carefully
- Check all `{ }` braces are balanced
- Check all lines end with `;`
- Try LEVEL 1 bypass (alternative code in same file)

#### "Cannot edit method"
**Cause:** Method is sealed or readonly
**Fix:**
- You should be able to edit. Make sure you right-clicked the correct method
- Try restarting dnSpy
- Make sure you're editing the Updata() method, not a property

#### Changes not saved
**Cause:** Didn't save module
**Fix:**
```
After compilation:
File → Save Module → Choose location → Save
```

### TK11.exe Issues

#### "File version is Wrong" error still appears
**Cause:** Running original TK11.exe instead of patched version
**Fix:**
```cmd
# Check which version you're running
dir TK11_PATCHED.exe
# Should exist and be ~373 KB

# Use patched version
TK11_PATCHED.exe
```

#### TK11_PATCHED.exe won't start
**Cause:** Bad compile in dnSpy
**Fix:**
```cmd
# Restore original
copy bin\original\TK11.exe TK11_PATCHED.exe

# Try patching again with simpler LEVEL 1 bypass
# See bin\scripts\patch_tk11_updata_method.cs
```

### Flashing Issues

#### "Write fail" with all firmware variants
**Possible causes:**
1. Bad USB connection
2. Radio not in programming mode
3. Wrong radio model
4. Bootloader very strict

**Fixes to try:**
```
1. Check USB cable connection
2. Turn radio OFF, then ON
3. Try different USB port
4. Update USB drivers
5. Try on different computer
6. Consider LEVEL 3 bypass (see COMPLETE_TK11_BYPASS.md)
```

#### Flash hangs at X%
**Cause:** Communication error
**Fix:**
```
1. Don't touch radio or cable during flash
2. Close other programs using serial ports
3. Try different USB port (avoid hubs)
4. Check Device Manager for COM port issues
```

#### Radio won't start after flash
**Cause:** Bad firmware flash (bricked)
**Fix:**
```
1. Don't panic - usually recoverable
2. Reconnect USB cable
3. Turn ON radio while holding special key combo (see radio manual)
4. Flash original firmware: bin\original\TK11_v5.00.09_ENG.bin
5. Use original TK11.exe for recovery
```

### USB TX Testing Issues

#### Still see "DISABLE" message
**Cause:** Firmware didn't actually flash
**Fix:**
```
1. Verify flash was successful ("Write success")
2. Check radio actually restarted
3. Try reflashing different variant
4. Verify correct channel (K38, 27.385 MHz)
```

#### USB mode not selectable
**Cause:** Wrong channel or mode disabled
**Fix:**
```
1. Must be on K38 channel specifically
2. Some channels may not allow USB
3. Check radio menu settings
```

#### No RF output
**Cause:** Multiple possibilities
**Fix:**
```
1. Check dummy load connection
2. Check antenna/dummy load switch
3. Verify PTT button pressed fully
4. Check TX power settings
5. Use spectrum analyzer to verify
```

## Technical Details

### Firmware Structure

```
TK11_v5.00.09_ENG.bin (357,976 bytes)
├── Header (possibly first 32 bytes)
│   └── May contain CRC/checksum
├── Code and Data
│   ├── ...
│   ├── 0x314D: TX Permission Mask ← PATCH HERE
│   ├── ...
└── Footer (possibly last 2 bytes)
    └── May contain CRC16
```

### TX Permission Mask (0x314D)

```
Original: 0x03 = 0b00000011
Bit 0: FM  (0x01) = ENABLED ✅
Bit 1: AM  (0x02) = ENABLED ✅
Bit 2: USB (0x04) = DISABLED ❌
Bit 3: ?   (0x08) = ?
Bit 4: ?   (0x10) = ?

Patched: 0x13 = 0b00010011
Bit 0: FM  (0x01) = ENABLED ✅
Bit 1: AM  (0x02) = ENABLED ✅
Bit 2: USB (0x04) = ENABLED ✅  ← CHANGED!
Bit 3: ?   (0x08) = ?
Bit 4: ?   (0x10) = ENABLED ← Side effect
```

### Firmware Variants Explained

| Variant | Strategy | CRC Location | Notes |
|---------|----------|--------------|-------|
| v3_minimal | No CRC, minimal change | None | Most conservative |
| v1_simple_crc16xmodem | Add CRC16-XMODEM | EOF-2 | Common format |
| v2_crc16ibm | Add CRC16-IBM | EOF-2 | Alternative algorithm |
| v4_end_of_file | CRC16-XMODEM | EOF-2 | Same as v1 |
| v4_header_0x0C | CRC16-XMODEM | 0x000C | Try header position |
| v4_header_0x10 | CRC16-XMODEM | 0x0010 | Try header position |
| v4_header_0x1C | CRC16-XMODEM | 0x001C | Try header position |
| v4_header_0x20 | CRC16-XMODEM | 0x0020 | Try header position |

**Why so many variants?**
- Bootloader CRC algorithm unknown
- CRC position unknown
- Testing multiple strategies increases success probability

### BK4819 RF Chip Limitations

⚠️ **Important:** The TK11 uses BK4819 RF chip which:
- Natively supports **FM and AM** modulation
- Does **NOT** have true SSB capability
- "USB mode" likely produces FM-modulated signal
- May not produce actual Upper Sideband signal

**Recommendation:** Use spectrum analyzer to verify actual modulation type.
